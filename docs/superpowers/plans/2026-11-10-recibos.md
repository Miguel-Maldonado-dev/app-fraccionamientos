# Recibos sin PDF almacenado: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cada pago guarda un JSON pequeño (`pagos.recibo`) y el recibo de 58 mm, con logotipo y QR, se genera como PDF al abrirlo. Desaparecen `pagos.file_data` y la dependencia de la edge function.

**Architecture:** Un módulo puro en `src/features/pagos/recibo/` define el JSON (Zod) y genera el PDF con jsPDF y `qrcode`. Las acciones de pago arman el JSON y lo incluyen en el mismo `insert`. La ruta `/api/recibos/[pagoId]` lee `referencia` y `recibo` con la sesión del usuario, valida el JSON y responde el PDF. Una migración agrega `recibo`, recrea dos vistas y elimina `file_data`.

**Tech Stack:** Next.js 16.3 (route handler en runtime Node), jsPDF 4.2, `qrcode` (nueva, versión fija), Zod 4, Supabase local con pgTAP, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-10-recibos-design.md` (aprobado).

## Global Constraints

- **No hacer commits.** El usuario hace todos los commits.
- **Next.js 16:** leer `node_modules/next/dist/docs/` antes de tocar el route handler o `next.config.ts` (AGENTS.md). No levantar el servidor.
- **Comprobaciones al cerrar cada tarea:** `npm test`, `npx tsc --noEmit`, `npm run lint`, `npm run build`. Si hay cambios de base, también `supabase db reset </dev/null && supabase test db </dev/null`, y luego recargar la demo con `docker exec -i supabase_db_app-fraccionamientos psql -U postgres -v ON_ERROR_STOP=1 < supabase/scripts/demo-local.sql`. Todos los comandos `supabase` llevan `</dev/null`.
- **No modificar migraciones existentes.** Los cambios de esquema van en una migración nueva (`supabase migration new recibos_json </dev/null`) con pruebas pgTAP. Los tipos se regeneran con `supabase gen types typescript --local > src/lib/supabase/database.types.ts </dev/null`.
- **Dependencias:** `qrcode` y `@types/qrcode` con versión exacta (`npm install --save-exact`); el lockfile se actualiza.
- **El recibo nunca rompe un pago:** armar el JSON no consulta servicios externos, y un fallo del logo no impide generar el PDF.
- **Textos del ticket exactos** (spec §4): "RECIBO DE PAGO", "Dirección:", "Residente:", "Periodo:", "Concepto:", "Vencimiento:", "Fecha de pago:", "Subtotal", "+ Recargo", "− Descuento", "TOTAL", "Referencia:", "Gracias por su pago", "WEADMI · Gestión residencial".
- **TDD:** la prueba primero.

## Review Focus

1. **Dirección, residente o concepto muy largos** (120 caracteres o más). Se ajustan en varias líneas dentro de 58 mm; nada se corta ni se sale de la página. Prueba en la tarea 1.
2. **Recargo o descuento en 0.** No aparecen en el JSON ni en el ticket, y el total coincide con el importe cobrado. Prueba en la tarea 2.
3. **JSON de una versión futura o corrupto** (`v: 2`, o sin `total`). La ruta responde 404 "Recibo no disponible", no un 500. Prueba en la tarea 2.
4. **Falla la lectura del logotipo.** El PDF se genera sin logo y se registra el error. Prueba en la tarea 1.
5. **Referencia con caracteres raros en el nombre del archivo.** El nombre se sanea, como hoy. La prueba existente de la ruta se conserva en la tarea 2.

### Task 1: Módulo del recibo: datos y PDF

**Files:**
- Create: `src/features/pagos/recibo/datos.ts` (+ `datos.test.ts`), `src/features/pagos/recibo/pdf.ts` (+ `pdf.test.ts`), `src/features/pagos/recibo/logo.ts`
- Modify: `package.json`, `package-lock.json` (`qrcode`, `@types/qrcode`)

**Interfaces:**
- Produces:
  - En `datos.ts`:
    - `reciboDatosSchema`, un Zod object con: `v: z.literal(1)`, `fraccionamiento: string`, `direccion: string`, `residente: string`, `concepto: string`, `periodo?: string`, `fechaVencimiento?: string`, `fechaPago: string`, `subtotal: number`, `recargo?: number`, `descuento?: number`, `total: number`.
    - `export type ReciboDatos = z.infer<typeof reciboDatosSchema>`.
    - `export function parseRecibo(value: unknown): ReciboDatos | null`.
  - En `logo.ts`: `export async function cargarLogo(): Promise<string | null>`.
    - Lee `public/brand/weadmi-logotipo.png` con `fs/promises` (ruta desde `process.cwd()`) y devuelve el data URL PNG en base64.
    - Lo guarda en memoria del módulo después de la primera lectura.
    - Si falla, `console.error` y devuelve `null`.
  - En `pdf.ts`: `export async function generarReciboPdf(datos: ReciboDatos, referencia: string, logo?: string | null): Promise<Uint8Array>`.
    - Página de 164 pt de ancho y alto calculado (primero se mide el contenido, luego se crea el documento con ese alto).
    - Margen de 8 pt, Helvetica, todo en negro.
    - Logotipo centrado de 148 × 31 pt cuando `logo` no es nulo.
    - Contenido y orden de la spec §4.
    - Importes con `formatMoney` de `src/lib/format.ts`.
    - Textos largos con `splitTextToSize`.
    - QR con `QRCode.toDataURL(referencia, { margin: 0, color: { dark: '#000000', light: '#FFFFFF' } })`, centrado, de 72 pt.
    - Las demás medidas quedan al criterio de quien implementa.
- Si jsPDF no funciona en Node dentro de Vitest o en el build, se permite `pdf-lib` (versión fija) manteniendo las mismas firmas. Anotarlo en el reporte.

## Resultado (2026-11-10)

Terminado: 697 pruebas pgTAP y 524 de Vitest en verde; `tsc`, lint y build limpios. Ticket de muestra: ~16 KB.

Decisiones durante la ejecución:
- "- Descuento" con guion ASCII (la Helvetica integrada de jsPDF no tiene el signo menos tipográfico).
- PDF comprimido por defecto; logo propio del recibo (`public/brand/weadmi-logotipo-recibo.png`, 444×92, aplanado sobre blanco) para que el ticket pese poco.
- `outputFileTracingIncludes` con la clave escapada `'/api/recibos/\\[pagoId\\]'` (en Next 16 es un patrón glob).
- El subtotal del recibo de cuota es el importe con el que se generó la cuota (total − recargo + descuento), no el precio vigente del concepto.

Pendientes (pueden esperar):
- Un tesorero podría editar `pagos.recibo` vía API directa (mismo modelo permisivo que ya aplica a `importe`); endurecer con permisos por columna más adelante.
- Sin `try/catch` alrededor de la generación del PDF en la ruta (un logo corrupto daría 500).
